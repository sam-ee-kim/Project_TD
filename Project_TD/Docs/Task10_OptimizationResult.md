# 작업 10 최적화 검증 결과

측정일 2026-10-20. 원본 보고서는 `Builds/StressTest/*.md`에 있어요(빌드 폴더라 git에는 올라가지 않아요).

## 측정 환경과 조건

- **장비**: Windows 개발 빌드(Mono), i7-1195G7 노트북, Intel Iris Xe 내장 그래픽, 1920×1080, 수직동기 끔
- **조건**: 45층 마지막 웨이브를 바로 끝내 46층으로 Tier 전환(35×35 → 37×37)
  - 타워: 경로를 따라 부지에 고르게 배치. 4개 중 1개는 PreferType + typePriority ["Special"] 타워
  - 웨이브: 290마리, 0.1초 간격으로 세 가지 구성
    - 일반 ×290
    - 탱커 ×290
    - fast·tank 8줄 교차
- **그래픽 설정**: 프로젝트 PC 설정 그대로(SSAO, HDR, 소프트 섀도 켬). 그림자 캐스케이드만 4 → 2로 바꿨어요.
- **실행 방법**: `TowerDefence/Build Stress Test (Windows)`로 빌드하고 `Builds/StressTest/StressTest.exe`를 실행하면, 자동으로 진행한 뒤 보고서를 쓰고 종료해요.

## 남은 문제 (결정 사항: 그래픽 설정 유지)

1. **60fps**: 내장 그래픽에서는 GPU 병목이에요. 프로젝트 PC 그래픽 설정(SSAO·HDR·소프트 섀도)을 그대로 두기로 해서 이번 작업에서는 미달로 마무리해요. 외장 그래픽 PC에서 다시 측정이 필요해요.
2. **1웨이브 GC (약 60B, 1초에 몇 번)**:
   - 원인: 발사 섬광 점광원이 켜질 때 URP 내부(`CreateShadowData`, `Setup Light Constants`)에서 생기는 할당이에요.
   - 해결책: 섬광 점광원을 빼면 없어져요(시각 효과가 바뀌어서 하지 않았어요).
3. **2웨이브 GC (1회 23,348B)**:
   - 몬스터가 처음 넥서스에 도착하는 경로가 처음 실행될 때 생기는 Mono JIT 할당으로 추정해요.
   - IL2CPP 모듈이 설치돼 있지 않아 확인하지 못했어요.
4. **층 전환 연출 시작 직후 약 115ms 프레임 1회**:
   - 맵 교체 프레임과는 다른 프레임이에요.
   - 프로파일상 CPU 작업이 아니라 D3D11 Present에서 GPU를 기다리는 시간이에요. 원인은 특정하지 못했어요.
5. **37×37 맵의 부지 수**:
   - 생성할 때마다 76~124칸으로 달라요. 100칸보다 적으면 타워 100개를 놓을 수 없어요(맵 규칙 문제).
   - 최종 측정 맵은 76칸이라 타워 76개로 측정했어요.
6. **준비 단계 스파이크 (약 480ms)**:
   - 스트레스 시작 때 45층 휴식에서 몬스터 표시 280개를 한 번에 미리 만들어서 생겨요.
   - 실제 게임에서는 웨이브 크기가 조금씩 늘어나 휴식 때마다 소량씩만 만들어요.
